# Glamsterdam gas changes, 16 November 2026: who can change the contracts that EIP-8037 and EIP-8038 touch

EXIT Protocol · 21 November 2026 · all times UTC

The chain facts were read on 16 November 2026 and are pinned to Ethereum block 26,428,440 (hash
`0x6efcbfcb8cd34749f55a2200d522c96c796e9cf0a6ce1a1c4db592757ee948b9`, 15:18:47). The EIP texts, the agendas and the other public
sources were read again on 18 November 2026 between 04:52 and 05:32, and once more on 21 November 2026 between 01:24 and 01:33,
after ACDE #249 of 19 November 2026. Both EIP texts were unchanged; what the 21 November reading found is marked "Update, 21
November 2026" below. Later changes will be added to this note as dated updates, and the text above them will not be edited.

EIP-8037 and EIP-8038 change what state creation and state access cost on Ethereum, and how gas is returned after a failed call.
The Ethereum Foundation's repricing-impact tool lists the contracts that appear in transactions that would have broken under the
new schedules. It does not say who can change a listed contract. We read the chain with one question: at one block, who could
change the code of the contracts that the public sources name?

Below, what we read on chain is kept apart from what the EIP authors, the Ethereum Foundation and auditors report. Every chain fact
below was read from two provider views and kept only when both agreed, except the older log windows and one log-range scan, which
were read on one provider and are marked so.

Terms used below:
- A proxy is a contract that runs the code of another contract, its implementation; whoever controls the upgrade path can switch
  the implementation.
- UUPS is a proxy form in which the upgrade function sits in the implementation code, not in the proxy.
- A Safe is a multi-signature wallet contract; a Safe module is a contract the Safe allows to execute transactions for it.
- State gas is the new EIP-8037 gas dimension charged for creating state (new accounts, new storage slots, code).

## What the two EIPs change

Both EIPs have the status Last Call (deadline 1 November 2026). The texts used here are EIPS/eip-8037.md at commit `5ef3801` and
EIPS/eip-8038.md at commit `f1ade09` of the ethereum/EIPs repository. On 18 November 2026 the files on master (commit `3db38a3`)
were byte-identical to them. Update, 21 November 2026: at 01:24 the files on master (commit `b055fee`) were still byte-identical to
them, and neither file has a later commit.

- EIP-8037 prices new state per byte: CPSB = 1,530 gas per state byte. A new storage slot is 64 bytes (97,920 state gas; the
  current GAS_STORAGE_SET is 20,000). A new account is 120 bytes (183,600 state gas); this one charge replaces three separate
  parameters used by different operations: GAS_CREATE 32,000 (CREATE, CREATE2), GAS_NEW_ACCOUNT 25,000 (CALL and SELFDESTRUCT to
  a new account) and PER_EMPTY_ACCOUNT_COST 25,000 (EOA delegation). Code deposit is 1,530 state gas per byte plus 6 execution
  gas per 32-byte word for hashing (today 200 per byte).
- A transaction still has one gas limit. The part of it above the EIP-7825 per-transaction cap of 16,777,216 (2^24) forms a
  state-gas reservoir. It is funded at transaction start (in the pre-execution phase, before the first call frame) only when
  tx.gas is above that cap; a later state-gas refill can credit the reservoir in any transaction. Every state-gas charge is
  drawn from the reservoir first and then from regular gas (gas_left). GAS / gasleft() returns gas_left only. When a frame
  reverts or halts, its state changes are rolled back and its state gas is restored to the frame's baseline; on an exceptional
  halt the frame's gas_left is consumed, so state gas that was drawn from gas_left is consumed with it, not returned (EIP-8037,
  "Gas accounting for halts and reverts").
- EIP-8038 raises access and write costs: COLD_ACCOUNT_ACCESS 2,600 -> 3,000; STORAGE_WRITE 10,000 (old-schedule equivalent
  2,800); ACCOUNT_WRITE 9,000 (old-schedule equivalent 6,700); CREATE_ACCESS 12,000 (old-schedule equivalent 7,000);
  STORAGE_CLEAR_REFUND 4,800 -> 11,616; access-list costs 2,000 per storage key and 2,900 per address. CALL_STIPEND stays 2,300.
  The three old-schedule equivalents are not parameters of today's schedule; the EIP derives them from today's composite costs and
  calls them approximate.
- Derived from these parameters (and equal to the figures published in the glamsterdam-gas-invariants repository): a cold SSTORE
  to a new slot costs 110,020 in all (12,100 execution gas plus 97,920 state gas); when no reservoir pays the state gas, all
  110,020 comes out of execution gas (Osaka 22,100). A warm first change of an existing slot costs 10,100 (Osaka 2,900); CREATE
  to an empty address costs 12,000 plus 183,600 state gas, 195,600 in all (excluding init code and code deposit).

## What the EF tool measures, and what it does not

The EF repricing-impact tool replays mainnet transactions of blocks 21,319,986 to 25,319,985 (3 December 2024 to 15 June 2026)
under both schedules. A contract is listed when it appears in a "potentially broken" (G4) transaction as the entry contract, the
out-of-gas site or the revert site. Being listed is not the same as being at fault: the EF entity report itself says tokens often
appear because a call fails inside their transfer code after another contract calls them. The data was generated on 24 August
2026, before later changes to the specification. The tool does not say who can change a listed contract. That is the question
this note answers with chain reads.

## Method and limits

Two keyless provider views; every call and raw reply is stored and replayed. The first view is MEV Blocker
(rpc.mevblocker.io). The second view is Pocket (eth.api.pocket.network) for eth_call, eth_getLogs and eth_getBlockByNumber, and
Flashbots (rpc.flashbots.net) for eth_getCode and eth_getStorageAt. Flashbots refused 10-call batches, so its reads were repeated in
5-call batches at the same block, and the last 90 code and storage reads of the second view (58 eth_getCode, 32 eth_getStorageAt)
were served by Pocket. Older log windows were read on the first view only. The classification needs the two views to agree on
every reply; they agreed for all 105.

Proxy evidence checked: EIP-1967 implementation, admin and beacon slots, the EIP-1822 PROXIABLE slot, ZeppelinOS slots, canonical
EIP-1167 code, the Safe singleton (slot 0 and masterCopy()), EIP-2535 facetAddresses(), proxiableUUID(), and upgrade selectors in
the implementation code. On the authority path, Safe owners, threshold, enabled modules and guard are read; for an AccessControl
implementation, the UPGRADER_ROLE and DEFAULT_ADMIN_ROLE members are read. NOT_UPGRADEABLE_BY_EVIDENCE needs code evidence (no
DELEGATECALL or CALLCODE whose target is not a constant or the contract itself inside its basic block, and no upgrade-type
selector), never an empty slot alone.

Limits: the block-local operand check marks many real contracts UNKNOWN; owner() is taken as the UUPS or diamond upgrade authority
without reading `_authorizeUpgrade` (marked "inferred"); timelock roles are not read; a CALL-forwarding upgrade
(deprecate-and-forward) is caught only through its selector; metamorphic redeploys are not considered. The INV figures are
heuristic pattern hits in verified source, places to look, not findings.
