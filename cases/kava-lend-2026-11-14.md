# Kava Lend, 14 November 2026: a BUSD interest index that divided by almost nothing

EXIT Protocol · 15 November 2026 · all times UTC; a time without a date is on 14 November 2026

The facts were read on 14 November 2026 between 17:26 and 20:42 UTC (one block time, of height 23,493,663, was looked up at 21:23 UTC). The state at 19:47 UTC (Kava height 23,494,664) is in "Status"; other current values carry the time they were read. Later changes on chain will be added to this note as dated updates; the text above them will not be edited.

On 14 November 2026, between 04:04 and 05:42, Kava Lend lent out 55,205,050.60 KAVA against BUSD that one account withdrew, loop after loop, against its own BUSD deposit, whose recorded size had grown by a factor of more than 200,000 within about three minutes. Kava Lend is the lending module (`x/hard`) of the Kava chain. By 12:08, 49.2 million of that KAVA had been bridged to BNB Smart Chain over LayerZero and sold; another 4.58 million had gone to five accounts on Kava.

We re-read the Kava chain, Kava EVM and BNB Smart Chain with one question: what did the chain show, and when?

Below, what we read on chain is kept apart from what Kava and the press report. Most key facts were re-read from a second provider (corrected 15 November 2026: this said a second, independent provider; that is not shown, because two endpoints may relay the same upstream provider). Two kinds of history are served publicly by one provider only: past Kava Lend module state (polkachu) and past BNB Smart Chain balances (blastapi); the text says which facts rest on them.

Kava and BNB Smart Chain are not covered by EXIT's API. This note is research done with public read-only endpoints.

Terms used below:
- **Cash, borrows and reserves.** A Kava Lend market holds cash (coins in the module account), lends out borrows, and keeps reserves for the protocol.
- **Supply index.** Kava Lend grows every deposit by a per-market supply interest index. A deposit's current size is its stored size times the index now, divided by the index when it was stored.
- **Base unit.** The smallest unit of a coin: 10^-8 BUSD; 10^-6 KAVA (ukava).
- **Liquidation auction.** When a borrow exceeds its limit, a liquidator can close it. The borrower's collateral (the lot) is sold in an auction for the borrowed coin.
- **OFT adapter.** A LayerZero OFT adapter locks KAVA on Kava. A matching token contract on BNB Smart Chain mints the same amount there.

## The code

- **Supply interest.** In Kava's public code (tag v0.28.2), `CalculateSupplyInterestFactor` in `x/hard/keeper/interest.go` divides the new supply interest by cash + borrows - reserves. It returns 1 only when that value is exactly zero; a tiny or negative value passes.
- **Utilization.** In the same file, the utilization ratio is clamped to at most 1 and to 1 for a negative total, so the borrow rate stayed capped while the supply index did not.
- **History.** The last functional change to this function is from 2021.
- **The running build.** The chain runs a build named `0.28.2-security.1`, whose commit is not public. A node running public v0.28.2 had the same app hash as a node running the security build at block 23,493,657 (18:11). We infer that the public code computes the same results on this path: a node that computed different results would have halted.

## How it can be closed

These are our recommendations, from the code and the chain state above:
1. **Stop new borrows against inflated claims now:**
   - set every Kava Lend borrow limit to 0 and BUSD's loan-to-value to 0;
   - if a governance vote is too slow, disable the module in a coordinated security release.
2. **Bridge.** The Kava OFT adapter has no pause function, but the Safe that owns it can remove the BNB Smart Chain peer.
3. **Fix the formula:**
   - accrue no supply interest unless cash + borrows - reserves is safely positive;
   - compute supply interest against total supplied;
   - cap how far the index can move in one block.
4. **Repair the records:**
   - reset the BUSD supply index to its value before height 23,484,806 (2.7620) and re-sync the deposits;
   - restore the 127 borrow records erased by the empty-lot liquidations;
   - decide how the community pool's unbacked claim is to be treated.
5. **Addresses others can trace.** The BNB Smart Chain address `0x37d732914f86cc6eb1e87419e3046a739f011042` received and sold the bridged KAVA. The operator of the collector `0x79001a5e762f3befc8e5871b42f6734e00498920`, which looks like an exchange or custodian deposit system, can identify whose deposits the four contracts held. The Solana address above is named in a Bridgers event string and was not read on Solana.

## What this shows, and what it does not

- **What the chain shows:**
  - a defect in Kava Lend's own code, reachable once the BUSD market's cash had run dry;
  - the transactions in which it took effect;
  - where the KAVA went;
  - that most of it was the community pool's.
- **What the chain does not show:**
  - who controls these accounts;
  - whether the two groups are connected;
  - why either acted.
  We draw no conclusion about intent.
- **Not covered here:**
  - the destination chains of the proceeds;
  - the services behind the deposit addresses;
  - what Kava's governance will do about the unbacked claims.
