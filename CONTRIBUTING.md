# Contributing to EXIT public documentation

Help make a supported answer or explanation easier to inspect. This repository contains public product documentation and selected authored case notes. It does not contain the complete research engine or unrestricted raw evidence.

## A useful correction

State the exact page or case, the observed problem and the smallest proposed correction. Link a primary source and identify its network, subject, chain position or observation time when relevant. Separate what the source establishes from an inference. A later observation does not silently replace an earlier knowledge-time answer.

For a website defect, give reproducible steps, browser/device, expected behavior and actual behavior. Use the issue forms. Do not add passwords, bearer keys, wallet recovery phrases, private investigations or personal identifying information.

## Pull requests

Keep a change focused. Explain why it improves accuracy, clarity, reproducibility or accessibility. Preserve the distinction between delivered, privately tested, planned and unknown. New product claims require source-bound evidence; an AI answer or model consensus is insufficient. Do not add copied provider responses or third-party media without a verified sharing right.

## Conduct

Participation follows the [code of conduct](CODE_OF_CONDUCT.md).

## Security and commercial requests

Sensitive findings belong in the [security process](SECURITY.md), never a public issue. See [support](SUPPORT.md) for private integration enquiries. A contribution, issue or research brief does not create a bounty, paid engagement, service entitlement or response deadline.

EXIT development continues after the finite first release. The [roadmap](ROADMAP.md) states the intended increments and their evidence requirements; elapsed time is not delivery.
