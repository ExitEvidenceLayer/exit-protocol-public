## 12 November 2026 update — higher free limits, the service-capacity view and API behaviour changes

- Limits since this day's service release: 50 completed answers and 150 attempts per key per UTC day; 1,500 attempts across the service
  per UTC day; lifetime totals of 300,000 attempts and 1,000 keys, which are never reset; 100 new keys per UTC day and 5 per network
  per UTC day. The proof of work for a new key stays at 16 bits. No key or counter was reset. CHANGELOG.md gives the earlier figures.
- GET /v0/early-access now carries a service_capacity block: service-wide counts of the attempts used and remaining today and in total,
  and of the keys registered and remaining. It holds no per-key or per-network figure.
- Once the lifetime attempt total is used, requests that need a research attempt are refused and no new key is issued (the enrollment
  reason is then CAMPAIGN_ATTEMPTS_USED). Reaching a lifetime total has no notice period.
- The peer-route known issue of 11 November (below) is fixed: a provider failure on GET /v0/research/ethereum/layerzero/peer is
  recorded as PROVIDER_UNAVAILABLE. Peer records written before keep METHOD.
- A malformed JSON request body (JSON_REFUSED) or a duplicate JSON key (DUPLICATE_JSON_KEY) answers 400. It answered 409 before.
- HEAD requests. Of the routes the service itself answers, only the console page / answers a HEAD request: sent without a query string
  and without a request body, it gets the GET status and headers and no response body. A HEAD request for any other service route
  answers 405 METHOD_REFUSED. The files under /v0/log/ and /openapi.json are static files served by the web server and answer HEAD like
  GET.
- Alert receivers: the check that a receiver's host resolves only to public addresses now also refuses 192.0.0.0/24, 192.88.99.0/24 and
  fec0::/10.
- API description 2026-11-12.1 (the same routes as 2026-11-04.1); the repository copy is the live file.
