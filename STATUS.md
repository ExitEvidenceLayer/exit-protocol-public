## 29 October update — free-service continuity and verifier hardening

- The initial free period still ends on 24 November at 12:38:20 UTC. A versioned continuation is now deployed: the same keys remain valid in the quota-limited free tier afterwards, with no fixed end date or automatic payment. Existing daily and lifetime caps, registration controls and revocations are retained; no user or quota was reset.
- The status route separates the initial period from the continuing service. First-period watches and binding lookups retain their original expiry; new-period ones retain their seven-day window. An announced service end must give at least 30 days notice.
- API document 2026-10-29.1 is live. Terms, privacy and the console status text match the continuation. The layout and styles are unchanged.
- The daily isolated host test was repaired and expanded: 26 modules / 703 executions pass on the installed release, including the continuation boundary/recovery controls. These are synthetic technical checks, not proof of total security or customer demand.
- The standalone Python verifier now rejects non-ASCII memo digits and invalid numeric/notary/message shapes, and distinguishes JSON-RPC provider failures. Existing valid proofs remain compatible. The website, API mirror and tools/ copy use the same corrected file.

## What completion means

The finite EXIT 3.0 technical scope was accepted on 26 October with its stated source, coverage and operating-evidence limits; [EXIT-3.0-SCOPE.md](EXIT-3.0-SCOPE.md) lists it item by item, with each item's status and limits. This is the first delivery milestone in one continuing development program. Future features and paid service rights require their own acceptance; technical completion is not a claim of universal coverage or demonstrated customer utility.

EXITP was created through Jupiter Studio / Meteora DBC; the official
mint was created before free API activation. The API opened at the actual timestamp above; the
previous planned sequence is not rewritten as an executed sequence. Paid API Pass
remains a separate release requiring actual receipt/wallet and security acceptance.

Free-serving v4 passed 44 source-bound tests as the actual target-host service user;
17 wrong-rule mutants were caught in prior isolated testing. Live state was backed
up encrypted and restored in an isolated directory: start time, usage and revoked
keys were retained; a stale database was rejected against the current trusted marker.
These are finite technical checks, not evidence of customer demand or total security.
The separate v4 clock-delta source review is now **ACCEPT / TECHNICAL_PASS**,
bound to the deployed v4 source. On the actual host, successful chrony synchronization
is now a required predecessor of the free service at boot; this was applied without
restarting the live service or changing its campaign clock. Finite testing and
separate source review are not a guarantee against every future defect.
